# M3 — Run economy, upgrades, speed

**Goal:** the in-run decision space is complete: tree upgrades, unit upgrades, tower levels/sell, cash spending, speed control, pause, real rewards.
**Depends on:** M2 tagged `v0.3.0-m2`.
**Sessions:** 2.

## Read (spec)

- §4.9 Run end + rewards
- §4.10 In-run economy and the upgrade panel (this is the core of the milestone)
- §4.11 HUD (speed control, upgrade button, pause)
- §6.1 Currencies (Cash rules), §6.2 XP (rewards side only)
- §13.5 Run summary
- §17.2 response style if a number is ambiguous

## Tasks

- [ ] Tree upgrade tracks (damage, attack speed, crit chance, crit damage, range, regen) as `.tres`; panel generated from data.
- [ ] Unit level 1–10 with cash cost curve; upgrade in place.
- [ ] Tower level 1–10, cost curve `base * 0.8 * 1.55^(lvl-1)`, sell for 70 % of invested.
- [ ] Transaction API (`SpendResult`) with affordability reason; hold-to-buy at 8/s without double-spend.
- [ ] "Next wave" bonus `10 + 2*wave` capped 120, with accidental-tap protection.
- [ ] `BattleClock` speed 1x / 1.5x / 2x with lock states and unlock popup (rewards wired to stubs).
- [ ] Pause menu: resume, restart (confirm), abandon (confirm), settings shortcut.
- [ ] Full `RunSummary`: coins, gems, XP, best wave, "new best", double-coins ad hook (stub).

## Acceptance

- [ ] Upgrading changes DPS measurably (a unit test computes expected DPS from data).
- [ ] Hold-to-buy 5 s never overspends and never goes negative.
- [ ] Speed 2x does not desync waves, timers, or animations of the HUD.
- [ ] Abandon == death at the same wave in terms of rewards.
- [ ] A skilled manual run reaches wave 15+ with M3 numbers; record it in `docs/BALANCE.md`.

## Watch out

- Rewards must be granted through `RewardBundle`, not by direct wallet writes.
- Cash is lost on run end — the summary must say so.
- Do not touch meta progression (workshop/magica/cards) in this milestone.

## Report

DPS table before/after, wave reached, tests, next command.
