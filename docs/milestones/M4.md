# M4 — Meta progression and persistence

**Goal:** progress survives restarts; all meta systems are data-driven and affect battle through one modifier pipeline.
**Depends on:** M3 tagged `v0.4.0-m3`.
**Sessions:** 3–4 (this is the largest content milestone — split it if needed, but keep the save schema whole).

> **M4a status (done, not tagged):** `SaveService` v2, `WalletService`,
> `LevelService`/`UnlockService`, Workshop (24 tracks + screen) and the
> ModifierService pipeline are implemented. Remaining tasks below are **M4b**
> (Magica, Cards, Missions, offline income); M4b tags `v0.5.0-m4`.

- §6.1 Currencies, §6.2 Levels, §6.3 Workshop, §6.4 Magica, §6.5 Cards, §6.6 Missions

## Tasks

- [ ] `SaveService`: atomic write, backup, checksum, `migrate()`, autosave hooks.
- [ ] `WalletService` with transaction log and typed results.
- [ ] XP/levels/unlocks data + `UnlockService`.
- [ ] Workshop: 24 tracks, cost curve `base * 1.18^lvl`, cap 50, buy + buy-max.
- [ ] Magica: 12 nodes, prerequisites, real-time timers, offline completion on boot, cancel refund 50 %.
- [ ] Cards: 12 cards, rarity, levels 1–5, shards, 4 equip slots, upgrade/equip flow.
- [ ] Missions: 3 daily + 5 weekly from templates, event-driven progress, claim once, reset 04:00 local.
- [ ] `ModifierService`: aggregates workshop + cards + magica + tree upgrades into final stats.
- [ ] Offline income on boot (timestamp delta, clamp by offline cap).

## Acceptance

- [ ] Research started, app killed, reopened after timer → completed with correct remaining time before.
- [ ] Workshop purchase persists and changes starting DPS (test compares two profiles).
- [ ] Equipping a card changes the same aggregated stats; unequip restores.
- [ ] Corrupted main save → backup loads, one-time toast, no crash.
- [ ] Missions reset correctly across a simulated 04:00 boundary; claiming twice is impossible.
- [ ] Fresh profile with onboarding completed reaches wave 10 with no meta upgrades.

## Watch out

- One aggregation point. If a stat is modified in two places, the milestone failed.
- All timers stored as UTC unix seconds; display in local time.
- Migration must be a pure function with a test per version step, even if only v1 exists now.
