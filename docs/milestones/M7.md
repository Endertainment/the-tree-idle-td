# M7 — Backend (FastAPI + Neon) and live features

**Goal:** accounts, cloud saves, weekly leaderboard, tournaments — with the client staying playable offline.
**Depends on:** M6 tagged `v0.7.0-m6`.
**Sessions:** 3–4 (split server and client integration into separate sessions).

## Tasks

**Server (`server/`)**

- [ ] FastAPI app, settings, async SQLAlchemy + Neon, Alembic baseline, Dockerfile + docker-compose, `.env.example`.
- [ ] `POST /auth/guest`, `/auth/refresh`, JWT, rate limiting.
- [ ] `GET/PUT /save` with revision conflict (409) and idempotency keys.
- [ ] `GET /config` remote config defaults + override merge.
- [ ] `GET /leaderboard`, tournaments list/standings/submit with plausibility validation.
- [ ] `POST /purchases/verify` (stub verification), `POST /ads/ssv` (signed), `POST /events`.
- [ ] OpenAPI docs, seed script, `server/SPEC.md` matching the implementation.

**Client**

- [ ] `ApiClient` integration: tokens, retries/backoff, offline queue, typed errors.
- [ ] Save sync: local-first, conflict resolution by revision, user-visible sync state.
- [ ] Leaderboard screen against the real API; tournament screen with cohort table.
- [ ] Weekly reset handling (Europe/Kyiv Monday 04:00 stored as UTC).

## Acceptance

- [ ] Two devices, same account → same progress; offline edits sync without loss.
- [ ] Leaderboard returns own rank; a fabricated run (impossible stats) is rejected.
- [ ] Weekly reset moves entries to the previous week without duplicate ranks.
- [ ] Server starts locally with one command; migrations run from zero.
- [ ] Client with the server down behaves exactly as before M7.

## Watch out

- Server is authoritative for placement and grants; never trust client-reported results.
- Keep `ApiClient` the only place with `HTTPRequest`.
- Do not store tokens in the save file or logs.

## Report

Endpoints live, sync behaviour, anti-cheat rules implemented, open risks.
